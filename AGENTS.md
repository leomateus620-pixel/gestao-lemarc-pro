# Project rules

- Auth calls on the login page and app gates go through `withTimeout` (src/lib/auth), and every signOut uses scope 'local'. Why: this stops endless loading screens on phones and keeps other devices signed in.
- The saved login is only cleared on a definitive server rejection (`classifyAuthError` in src/lib/auth/sessionPolicy), when the max age since the last login is reached, or when the user taps sign out / clear session — never on timeout, offline or 5xx. Why: field technicians with bad signal must stay signed in.
- Login presentation preferences and administrator-panel visibility never grant access or initiate OAuth; keep them separate from session authorization. Why: shared devices and URL parameters cannot establish a user's role.
- The app reloads itself when `/version.json` (server route, no-store) reports a build id different from the embedded `__APP_BUILD_ID__` (vite define); `/login` reloads immediately, other screens only when nothing is being edited, and a failed check never touches the session. Why: open tabs/PWAs otherwise keep running stale login code.
- Admin access tools (reset technician password, sign out all their devices) live in `adminManageTechnicianAccess`: admin role checked on the server, never on admins or oneself, service role only inside the handler, password never stored or logged, audit row in `admin_password_resets`. Why: avoids privilege escalation and leaked credentials.
- Login failure diagnostics are inserted from the browser into `login_diagnostics` with masked e-mail only; a DB trigger enforces size, masking, rate limits and 30-day retention, and only admins can read. Why: lets admins debug technicians' logins without exposing credentials.
